# 内置 Browser 执行与候选归档

仅在当前任务需要生成或重新生成图像时读取。提示词数量与候选数量以 [SKILL.md](../SKILL.md) 为准，Preview 方向设计见 [preview.md](preview.md)，正式资产变化边界见 [contracts.md](contracts.md)。

## 执行入口与项目命名

- 默认使用当前环境的内置 Browser 操作已登录的 ChatGPT Web，先读取控制接口说明。用户指定平台、浏览器或账号时沿用其指定会话，保持现有登录；平台不支持项目或聊天组织时，保存可核验的任务链接与本地轮次记录。
- 新一轮作品资产制作在 ChatGPT Web 新建一个专用 Project，命名为 `WALLY｜作品名｜静态资产｜YYYYMMDD-R01`。使用真实作品名和当天日期；重名时递增轮次。此处 Project 指网页项目，不创建本地 Project Shell 或 Codex 新任务。
- 同一制作批次中的 Preview 和全部资产放在该项目；续作或中断恢复先根据记录复用原项目，不因每次调用或每项资产重复建项目。用户明确指定已有项目时使用该项目。
- 在项目说明中只保存各候选共用的剧本调性、世界事实、不可变条件和单次生成一版的要求。Preview 尚未选定时不写入某个候选的风格为全局默认；选定后再登记选定风格和参考。
- 命名后从页面核实实际项目名称与 URL，按 [候选生成记录](../templates/generation-record.md) 归档。创建或命名失败时保留实际状态，不声称已完成。

## 每项资产独立聊天

- Preview 聊天命名为 `PREVIEW｜作品名｜全局视觉方向｜R01`。
- 正式资产聊天命名为 `资产编号或稳定名称｜资产自然名称｜产物类型｜R01`。如基础人物、该人物场景状态、角色比例、基础道具、道具状态、地点、地点九宫格及地点四宫格，分别有自己的聊天。
- 一个资产的一轮候选共用该资产聊天，按版本顺序逐次生成；不为每个版本新开聊天，也不把其他资产插入其中。新的探索轮次新开带递增轮次的聊天。
- 衍生资产也单独开聊天，显式上传用户已选定的基础资产原图与必要的全局风格参考；不靠基础资产聊天记忆代替引用，不上传未选定的候选作为共同依据。
- 聊天创建后命名，核实它归属当前项目，并登记实际名称和 URL。只上传当前任务必需、项目所有或用户授权的材料。

## 平台能力与布局参考

- 开测前核实当前可用模型、实际选中版本及所需功能，按本轮目标选型并记录依据。旧版可用于复现或对照；新一轮测试应重新检查适用版本，不机械沿用旧参数，也不把特定版本写成永久默认。提示词参数与页面设置都要核对，提交后检查实际结果。
- 比较风格时保持模型与主要参数一致；比较模型时复用同一组提示词与代表画面，并记录各版本实际设置。仅在某个模型与参数组合下观察到的效果，只在该测试范围内作结论。
- 先从当前页面核实画幅、参考图上传和参考权重控件是否存在。若有画幅控件，按当前产物合同设置；提示词仍保留合同中的画幅要求。无对应控件时不编造设置步骤或声称已设置，只记录实际可用能力。
- 使用类型文件链接的可选布局板时，先转成 PNG，再作为构图参考上传，说明只参考分区与视图位置，不继承占位形状、颜色或人物外观。只有页面实际提供参考权重控制时才设置低权重；没有该控制时只使用上述用途说明。无法上传时跳过布局板，保留完整文字布局契约；必需基础参考图仍按类型依赖处理，不能跳过。
- 平台设置以实际操作为准，下载后核对原图尺寸。画幅不符按下方技术修正规则处理，不通过裁切、拉伸或重绘原图冒充合格产物；不把提示词中的比例文字当成已实现的设置。

## 提示词与顺序执行

1. 先完成该资产整组不同的完整生成输入（正文与所需参考），记录每版的方向名、差异和保持不变项。Preview 同时记录方向与代表画面，每个组合各用一条完整输入。版本号按 `V01` 起连续编号，留在聊天说明、文件名和记录中，不要求生成进资产图。用户要求先在聊天展示提示词时，先展示再按其生成授权执行。
2. 在本资产聊天中附所需参考，按实际平台能力核对风格、身份或构图的引用用途；风格名称不能代替参考接入。在项目或聊天说明中维护共同材料与引用边界，未选候选只可作为明确指定的测试输入，不自动成为后续版本的全局风格或身份依据。Preview 每版正文遵循“整体风格＋构图描述”，不重复附上记录字段、评审历史或流程说明。
3. 一次只提交一套完整提示词，要求每张为独立画面。平台原生返回多张时分别核看，它们仍属于同一输入，不能增加风格方向数。等待当前输入生成、核看及所需归档完成，再提交下一套；不使用“再来一张”替代完整输入。
4. 一张图可以包含类型合同要求的三视图或多宫格，但只能代表一个候选版本；不能把多个版本合在一张生成图里充数。
5. 同一候选包在已授权范围内连续执行，途中不要求用户逐张批准；完成整组后一次展示供用户选择。恢复任务时先核对记录及聊天中的实际结果，不重复提交已完成候选。

## 原图验收、技术修正与停止

- 用户要求不下载时，只在网页核看并记录任务链接、实际回图与问题；完成度按该授权范围判断，原图归档单独记为未下载。截图可以作为核看证据，不称为原图。
- 接受所用平台的原生生图结果，并核对下载原图与页面可见生图卡的内容一致。普通代码生成的 PNG、PDF、SVG 或附件不作为生成资产；截图只作证据，不代替原图。
- 下载后检查原图的实际尺寸、身份、风格、视图、网格和结构。每版使用 [review-protocol.md](review-protocol.md) 与对应类型清单，Preview 使用其方向与调性检查。
- 客观错误可在同一候选后提交一次最小修正，保留本版方向、已选参考与固定布局。技术重试归属于原版本的尝试记录，不计为额外设计方案。
- 同一候选修正后仍失败则标记不合格，保留证据，可继续不依赖该失败的其他候选；不无限重试，不自动另换风格凑数。明显重复的方向也不计为不同合格候选。
- 只有达到本轮要求范围的不同完整输入及对应可比较结果，才标记生成与核看完成。Preview 完整探索按方向及代表画面逐项核对；用户限定的专项测试按其范围核对。原图归档、技术合格与用户选择分别记录；缺图、不合格或方向重复导致不足时，报告具体缺项，不宣称已完成选型。
- 遇到登录、额度限制、不可用的内置浏览器、无法创建项目/聊天或无法下载原图时，记录停止位置及已完成版本。登录交由用户完成；不偷偷换服务、重建全部任务或让用户自行搬运提示词。

## 下载、交付与用户选择

在项目输出边界保存一份运行记录，使用 [候选生成记录](../templates/generation-record.md)；一次性任务使用专属本地输出目录。为每版保存独立完整提示词、实际提交与修正记录、原图、生成时间、尺寸、SHA-256、项目/聊天 URL、原生生图证据和技术判定。建议文件名为 `资产键-R01-V01-prompt.txt`、`资产键-R01-V01-original.<原始扩展名>`；保留原始图片字节，不覆盖旧轮次。

完成整组后按版本号返回全部候选图片及简短差异、适用点和技术问题，方便用户直接说“选 V03”。本地比较页只能作为附加交付，不替代各版本原图。

用户明确选择后，在同一记录中写入选定版本、用户原话和选定原图位置；技术 verdict 与用户选择分别保存。Preview 选择更新全局风格，正式资产选择成为其衍生资产的参考来源。只继续用户已授权、且依赖已被选定的下一项工作。
