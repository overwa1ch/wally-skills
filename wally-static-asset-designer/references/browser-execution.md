# 内置 Browser 异步提交与候选归档

生成或恢复图像任务时读取。候选数量见 [SKILL.md](../SKILL.md)，Preview 输入见 [preview.md](preview.md)，正式资产合同见 [contracts.md](contracts.md)。本文件管理网页任务与文件，不要求 Agent 查看图像内容；视觉审查见 [review-protocol.md](review-protocol.md)。

## 网页制作项目

- 使用内置 Browser 操作已登录的 ChatGPT Web，先读取控制接口说明。用户指定平台、浏览器或账号时沿用其会话。
- 新制作批次建立专用 ChatGPT Project，命名为 `WALLY｜作品名｜静态资产｜YYYYMMDD-R01`。续作或中断恢复复用记录中的项目；同一批次的 Preview 和正式资产共用项目。此处 Project 是网页项目。
- 项目说明只保存共用的剧本调性、世界事实、不可变条件及每条输入生成独立候选的要求。已选风格按实际适用范围登记；探索中的候选保持各自独立。
- 核实项目实际名称、URL 和聊天归属，保存至 [候选生成记录](../templates/generation-record.md)。平台不支持项目组织时，保留可核验的聊天链接与本地批次记录。

## 每条输入独立聊天

- Preview 每个“方向 × 代表画面”各建一个聊天，命名为 `PREVIEW｜作品名｜R01｜V01-F01`；`V01` 对应方向，`F01` 对应代表画面。
- 正式资产每个候选各建一个聊天，命名为 `资产键｜自然名称｜产物类型｜R01-V01`。新的输入使用新聊天，避免继承其他候选的生成历史。
- 每个聊天都提交完整提示词，并单独附上该任务所需的参考图。依据记录核对附件名称、来源与用途，不依赖其他聊天的记忆。只上传本任务必需且已获授权的材料。
- 已经提交的历史任务按原链接恢复，不为迁移聊天结构重复提交。新增任务使用独立聊天。

## 准备本轮队列

- 先完成本轮不同的完整输入。为每项登记稳定任务键、轮次、候选版本、Preview 画面编号、提示词与参考位置；各项独立可执行，不使用“同上”或“再来一张”。
- 核实当前页面的实际模型和可用设置。风格对照保持模型与主要参数一致，模型对照复用同一组输入；记录真实可用的画幅、附件及参考设置，没有的控件不声称已设置。
- 可选布局板先转成 PNG，上传时说明只参考分区和视图位置；仅在页面提供权重控件时设置低权重。无法上传布局板时保留完整文字布局要求。必需的已选基础资产须实际接入；尚未获得选定基础的衍生任务保持受阻，不能用未选候选替代依赖。
- 将执行进度及时写入队列：`prepared`（待提交）、`submitted`（已确认提交）、`generating`（生成中）、`generated`（已返回结果）、`archived`（原图已归档）、`failed`（明确失败）、`blocked`（依赖或平台受阻）。提交回执不明时单独记录，先查询原聊天再决定后续动作。

## 持续提交、轮询与收集

1. 取一项已准备好且依赖满足的任务，新建并命名独立聊天，附参考并发送完整提示词。每条输入要求独立候选；类型合同需要的九宫格等仍是一张候选图。
2. 从页面确认消息已发出、附件已关联，并记录聊天 URL、任务键和提交时间。确认的是提交成功，**不用等图片生成完成**。
3. 立即取下一项就绪任务，继续创建聊天、发送提示词。前一张的生成、下载和归档都不是下一条提交的前置条件。
4. 提交过程中可顺路收集已经完成的结果。就绪任务发完或平台限制继续提交时，轮询已提交聊天的任务状态；检查一轮后仍在生成的任务保持原状态，转向其他可做工作或适度等待后再查，避免停留在单张图上反复刷新。
5. 对已完成任务下载原图、写入文件位置和元数据。平台一次返回多张时全部保留并关联同一输入，不因此增加方向数。收集动作完成后继续派发允许提交的新任务或检查其他在途任务。
6. 本轮所有任务都有明确结果后，汇总全部候选交人审查。缺图、失败、仍在生成和受阻项分别列明；未齐的候选包保持未完成状态。收到人工意见后才执行获授权的下一轮。

同一浏览器会话的界面操作由一个执行者串行完成，已提交任务留在平台运行。平台实际并发量以回执和限制为准，不预设固定数量。出现并发上限时先收集在途结果，允许继续后恢复队列；批量授权只覆盖本轮任务，不自动扩展候选数量。

## 文件收集、失败与恢复

- 通过原生生成结果的下载入口取得原图，以聊天、消息或任务记录关联文件。保留原始字节；截图仅作操作证据，代码附件不作为原生生图结果。
- Agent 只核对任务与文件对应关系、文件可读取性、格式、尺寸、SHA-256 和原图是否保存成功。图中身份、风格、结构、视图数量和整体效果由人审查；发现尺寸等元数据与要求不符时照实记录，保留原图交人判断，不自动重绘。
- 用户要求不下载时，保存网页结果位置，下载状态记为“按要求未下载”；网页结果也交给人审查。
- 网络或平台明确报告提交/生成失败时，可按原输入重试一次并记录尝试号；先确认原任务已失败，回执不明或仍在运行时不重复提交。下载失败只重试下载，不重发生图。
- 限额、登录、不可用浏览器等阻碍新提交时，记录队列位置，保留在途任务；能够收集的已有结果继续归档。登录交由用户完成，不擅自换账号或服务。
- 恢复时先按记录查询已有任务，再提交尚未发送的条目。已返回或已归档的候选保持原任务及文件，失败尝试不占用新候选版本号。

## 整轮交付与人工审查

按 [候选生成记录](../templates/generation-record.md) 保存每条输入、参考、聊天链接、提交与完成时间、执行状态、原图及元数据；如有重试，保留全部尝试。建议文件名包含资产键、轮次、版本和 Preview 画面编号，例如 `preview-R01-V01-F01-original.png`，以实际原图扩展名为准。

按版本号展示本轮全部候选，附各输入的简短设计意图和实际执行状态，不给出 Agent 的视觉评分、排序或筛选。可生成汇总页供人看图，但原图仍可逐张访问。

第一轮生成结束即进入人工审查；后续各轮同样执行。人的审查原话、选择和修改要求写入同一记录。用户明确选定后登记版本与原图，更新其适用的全局风格或基础资产引用，再继续已授权且依赖已满足的工作。
