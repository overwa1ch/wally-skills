# 内置 Browser 异步提交与候选归档

生成或恢复时读取本文件与[候选生成记录](../templates/generation-record.md)。候选数量由 [SKILL.md](../SKILL.md) 维护；起草或修改才读 [Preview](preview.md) 或[正式资产合同](contracts.md)。Agent 只处理文字输入、网页回执和文件元数据，参考图与回图均交人审查。

## 批次与独立聊天

- 读取控制接口说明，使用内置 Browser 操作已登录的 ChatGPT Web；用户指定平台、浏览器或账号时沿用其会话。同一浏览器会话只有一个界面执行者，页面操作串行，已提交任务在平台异步运行。
- 新批次建网页项目 `WALLY｜作品名｜静态资产｜YYYYMMDD-R01`，续作与恢复复用记录中的项目，Preview 和正式资产共用。项目说明保存共用剧本调性、世界事实、不可变条件及每条输入独立候选要求；已选风格标明适用范围，探索候选各自独立。
- 核实并记录项目名称、URL 与聊天归属。ChatGPT 项目路径可能附带名称 slug，按同源、完整项目 ID 与页面归属核对，不用整段路径前缀代替归属证据。平台无项目组织能力时，保留聊天链接及本地批次记录。
- 每条完整输入新建聊天：Preview 用 `PREVIEW｜作品名｜R01｜V01-F01`（方向 × 代表画面），正式资产用 `资产键｜自然名称｜产物类型｜R01-V01`。每个聊天发送完整正文，并单独上传该项必需且已获授权的参考；核对附件名称、来源和用途。历史任务沿原链接恢复，不为调整组织结构重投。

## 平台能力与布局参考

- 核实实际模型、画幅、附件与参考设置，记录真实可用值；菜单中的模型须核实已选状态，可见的选项文字不能证明已选。风格对照保持模型与主要参数一致；模型对照复用同一组输入。缺少控件时不声称已设置。
- 可选布局板转 PNG，说明仅参考分区和视图位置；有权重控件才设低权重，无法上传时保留完整文字布局要求。必需的已选基础资产必须实际接入；缺少选定基础的衍生任务记 `blocked`，不以未选候选替代。

## 提交核验

执行定稿输入同样完成项目设置、逐聊核验、原图归档与人工交付。按下表保存实际核验结果及时间；任何前置项未确认时，任务保持 `prepared` 或记 `blocked`，停止该项新提交。

| 时点 | 必须核实的页面事实 |
| --- | --- |
| 批次首条提交前 | 在支持项目说明的平台，填入本批共用说明，执行实际 Save / 保存动作，再重新打开同一项目设置，回读持久化文本与预定说明一致；记录项目 URL、说明内容或位置及回读时间。续作核实已存说明即可。文本已填入、关闭弹窗和提交后补存均不能充当提交前证据。 |
| 每个新任务填写前 | 确认目标项目、空白新聊天且没有已有用户轮次，页面若已有聊天 ID，核对它未出现在本轮已提交列表；每个聊天内核实实际模型与主要参数，主页设置不代替逐聊核验。确认后按任务键核对来源，用已装载的对应定稿原文填写，附所需参考并发送；不在旧聊天输入框中准备下一候选。 |
| 每个任务发送后 | 确认实发全文与定稿一致、该消息的附件数量及关联正确（零附件也核实）；依据已观察的附件节点，消息操作图标不算附件。核对最终聊天 URL / ID 与本轮已提交项均不重复，记录回执、提交时间并核实名称；平台在首条消息后才允许命名时，此时补名。未得到这些事实前不记作独立提交成功。 |

## 定稿原文一次装载

同批已定稿原文一次读入持久 CUA 会话，填写与实发全文比较复用同一数据。已有变量可直接沿用；从 UTF-8 文件装载时可在技能目录运行一次，与本轮文件读取合并调用：

```sh
python3 scripts/cua_payload.py --source /absolute/project-instructions.txt /absolute/V01.txt /absolute/V02.txt /absolute/V03.txt /absolute/V04.txt
```

把输出的 JavaScript 数据声明放进下一次 CUA 调用，与已观察的目标操作合并。`staticSources` 按命令中的文件顺序保存 `{path,sha256,text}`；如 `staticSources[1].text` 为 V01。原文、换行和 SHA 保持源文件字节对应；普通执行无需读脚本源码。源文件修改或会话重置后重新装载，防止沿用旧稿。只在已获支持的页面读取接口内比较完整文本，返回相等结果、来源与回执；源文件 SHA 本身不能代替页面实发核验。

## 一个记录，三个执行阶段

先完成本轮不同的完整输入，标记 `prepared`（待提交）。按候选生成记录保存稳定任务键、轮次、版本、Preview 画面编号、独立聊天、完整输入及参考位置；每项独立可执行，不用“同上”或“再来一张”。共用批次事实保存一次，各任务引用；任务自己的回执、时间、参数、原图元数据和全部重试仍逐项保留。输入定稿后直接沿记录执行，更新变化项，不反复输出完整提示词和整表。

| 阶段 | 页面动作与完成证据 | 接续 |
| --- | --- | --- |
| 提交 | 从 `prepared` 取依赖满足项，按[提交核验](#提交核验)完成项目、空聊天与逐聊设置核验，发送完整输入，取得独立聊天回执后记 `submitted`。 | 立即提交下一就绪项，不等出图或下载；可顺路收集已完成结果。 |
| 回收 | 就绪项发完或并发受限后，按原链接检查在途任务：生成中记 `generating`，已返回记 `generated`；下载全部原生结果，验证文件并记录后记 `archived`。 | 每项每轮检查一次，已归档项退出轮询；先处理其他可做工作，整轮无变化时适度等待后再查。平台允许后恢复提交。 |
| 交付 | 本轮任务均有明确结果后，按版本号汇总全部候选及其输入意图、实际执行状态，执行[人工审查流程](review-protocol.md)。 | 缺图、仍生成、失败、受阻分别列明，未齐包保持未完成；首轮及后续轮次均停在 `pending_human_review`，收到人的意见后才落实获授权的下一轮。 |

- 已观察且目标明确的连续动作在同一工具调用内完成，动作后读取相关最新状态。有效定位可复用；发生导航、未知控件或错误时重新发现，先确认页面上下文，不跨未知页面猜控件。证据不清时扩大读取，不略过提交确认或隐去失败。
- 页面返回按当前阶段保留所需控件与核验事实：项目归属、设置回读、空聊天、逐聊实际模型与参数、完整正文及附件确认、唯一回执 URL / ID、任务与文件关联。完整输入从定稿源文件读取并核对页面实发内容，返回确认结果及来源位置，避免重复输出正文与无关页面。
- 平台实际并发量由回执与限制决定，不设固定并发数；批量授权只覆盖本轮候选。每条输入要求独立候选，九宫格等类型板式仍是一张候选图；平台返回多图时全部保留并关联同一输入，不增加方向数。

## 原图与元数据

- 从原生生成结果的下载入口取原图，保留原始字节，按聊天、消息或任务关联文件。截图仅作操作证据，代码附件不算原生生图结果。
- 核对对应关系、可读取性、格式、尺寸、SHA-256 和保存成功；记录提交与完成时间、模型及实际参数。平台未提供准确完成时间时标明未获取，另记结果观察时间，二者不混用。尺寸等元数据不符时如实登记，保留原图交人判断，不自动重绘；身份、风格、结构、视图数及整体效果均由人审查。
- 文件名建议含资产键、轮次、版本和 Preview 画面号，例如 `preview-R01-V01-F01-original.png`，保留实际扩展名。用户要求不下载时记录网页结果位置与“按要求未下载”，同样交人审查。

## 失败与恢复

| 观察到的状态 | 动作 |
| --- | --- |
| 新聊天操作后仍停留在旧会话，尚未发送 | 保留旧任务；平台有网页项目时，返回记录中已核实的项目 URL，从当前页面可见的新聊天入口重进，再执行填写前核验。仅有输入框或模型控件不能证明新会话建立；仍无法确认空会话时保持 `blocked`，不反复点击原入口或填写下一候选。 |
| 提交回执不明 | 单独记录原聊天及查询结果，先查原任务；仍在运行或无法确认失败时不重投。 |
| 网络或平台明确报告提交 / 生成失败 | 先查询原任务；确认没有可下载的原生结果且任务已失败后记 `failed`，按相同输入最多重试一次，保留尝试号、失败信息及新结果；失败尝试不占新候选版本号。 |
| 错误文案与可下载原生结果并存 | 保留原图和错误信息，核对任务关联及文件元数据，视觉可用性仍交人审查；不仅凭错误文案重发生图。 |
| 发送后发现共用旧聊天或前置设置缺失 | 记录实际提交、偏差与受影响版本，保留在途任务并归档结果；停止新提交，不以补存配置或擅自追加生成追溯修复本轮。后续动作按用户授权和预算处理。 |
| 只有下载失败 | 只重试下载，不重发生图。 |
| 限额、登录、浏览器不可用或依赖缺失 | 记 `blocked` 与恢复位置，保留在途任务，继续归档可收集结果；登录交用户，不自行换账号或服务。 |
| 中断后恢复 | 先按记录查询已有任务，再发尚未发送项；已返回 / 已归档项保留原任务和文件。 |

## 人工交付边界

全部候选原图可逐张访问，也可汇总展示；输入、版本、结果和聊天一一对应，不由 Agent 视觉评分、排序或筛选。人的审查原话、时间、选择及修改要求写回同一记录。用户明确选定后登记版本和原图，更新适用的全局风格或基础资产引用，再继续已授权且依赖满足的工作。生成、归档、人工审查和明确选定分别记录。文件齐全与流程符合合同也分别记录：汇总前核对设置回读发生在首条提交前、聊天 URL 唯一性及全部失败 / 偏差说明；后补设置不能改变原提交时的事实。
