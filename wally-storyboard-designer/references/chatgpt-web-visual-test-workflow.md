# 按场景生成故事板与分镜表

用户要求执行网页生成时读取。使用内置 Browser 和已登录的 ChatGPT Web；遵循用户指定的项目或目的地。

## 准备场景材料

1. 读取本次范围、产品、网格、图数和版本要求，核对源稿已有的场景及镜号。保留各场完整内容和适用的全局设定、台词、声音、参考绑定及衔接；每张图的镜号选择另写，不把场景材料继续切成缺失上下文的页包。
2. 剧本、导演脚本、表演设计、表格和可读文件均可直接使用。表演设计等同于导演脚本；上传时说明其作为本场镜头依据的用途，保持原文件内容与格式。
3. 只对真实缺失、歧义或平台限制处理依赖问题。清单、固定解析格式、本地分页程序及新建 ChatGPT Project 均不作为普通生图的前置条件。

## 创建聊天与上传

### 故事板

- 有几个源场景，就创建几个独立聊天。名称清楚标明“故事板”、原场景编号与名称。
- 在各聊天上传该场完整材料、适用的全局设定和当前要求使用的参考。

### 分镜表

- 先建立一个可识别的静态资产基础聊天，一次上传本次全部静态资产，说明对象、参考用途和文件名的对应关系。核对上传与绑定完成后再分支。
- 从同一个上传完成的基础聊天，为每个场景各创建一次分支；分支名称标明“分镜表”、原场景编号与名称。所有分支继承这批资产，无需逐场重传。
- 在各场景分支提供该场完整导演脚本／表演设计及适用的全局设定，明确使用的资产绑定。只生成本场镜头；基础聊天的其他资产不成为新增剧情。
- 实际分支或附件继承不可用时，说明具体限制，不默认为每页另建聊天或重复上传全部资产。

## 提交与连续生成

1. 按产品读取 [故事板固定提示词](../templates/storyboard-prompt-template.md) 或 [分镜表固定提示词](../templates/shot-table-prompt-template.md)。一次提交其短任务正文和绘制正文，保持原文及顺序；把场景、镜号范围、网格和输入用途说明放在独立段落。不要先单发短任务触发生成。
2. 同场全部图片在该场聊天或分支内生成。每张说明对应镜号；若一次调用只能生成一张，就在同一聊天继续下一张，不因分页新建聊天或分支。
3. 区分页数与同页备选版本。按本次要求完成图数；未要求备选时，每页只生成一版。换版本时保留同一页镜号，说明生成另一张独立图像。
4. 核对每张图的网格、镜号、缺失或重复镜头及资产对应。对明确的生成偏差定向重试，保留已经正确的原图；连续失败时报告具体问题，不反向改写有效脚本来迁就结果。

## 原图交付与后续确认

通过原生生成图卡下载原图，核对下载内容与图卡一致；保留场景、镜号、聊天位置及文件的对应关系。无法取得原图时如实报告，不用截图或代码绘图冒充原生成结果。

先交付完整网格原图供用户审查。只有明确授权后才自动裁切、重组或制作完整图文成品；说明将处理哪些图、采用哪份文字依据及交付形式。当次任务已明确包含这些操作时视为已确认，无需重复询问。后续执行细节见 [裁切与图文成品](paginated-review.md)。
